# 드래곤 러쉬 개발 인수인계 (2026-11-12)

이 문서는 현재 코드의 상태를 요약한다. 작업을 시작할 때 `AI_README.md`와 `coding_convention.md`를 먼저 읽는다. 상세 규칙은 `docs/game-design.md`, 전투와 AI 계약은 `docs/combat-design.md`, `docs/ai-interface-spec.md`, `docs/combat-ai-spec.md`를 따른다. 과거 작업 지시는 Git 이력에서 확인한다.

## 현재 상태

- 웹에서 로컬 및 Socket.IO 온라인 보드 게임을 플레이할 수 있다. 최대 4인, 보드 봇과 실시간 2D 탑다운 PvP/PvE, 각각 분리된 보드·전투 AI 학습 환경이 있다.
- 현재 보드 규칙 버전은 `rush-3`이다. 시작 방어막은 없다. PvP 승자는 패자의 코인 절반과 모든 아이템에 더해 코인 30개를 받고 HP를 완전히 회복한다. 3번 칸은 보물 상자, 9번 칸은 약초 군락이다.
- 상대 1명과 같은 칸에 서면 결투 확인 화면을 보여 준다. PvP 보호 라운드 1~2와 안전 칸은 현재 규칙의 예외다. 상점은 구매 가능한 아이템이 없어도 방문 화면을 보여 준다. 해당 화면은 말이 착지한 직후 표시된다.
- 이벤트 카드는 보통 속도에서 총 3.33초(등장 200ms, 뒤집기 180ms, 읽기 2.7초, 퇴장 250ms) 표시되고, 알림은 약 6초다. 보드 칸에는 hover/focus 설명이 나온다. 전투 기본 공격은 클릭/터치 누르기이고 키보드·게임패드도 지원한다.
- 로비·보드·결투·용전에 사용자 제공 `apps/web/public/assets/audio/bgm/dragon_foothills.mp3` 한 곡을 사용한다. 브라우저 음향 정책에 따라 첫 사용자 동작 뒤 재생된다. 기존 절차적 BGM은 제거했다. SFX는 기존 로직을 사용한다.
- 검사·궁수의 초상은 다른 직업과 같은 흉상 구도로 맞췄다. 봇의 “무작위”는 시작 시 고른 전략을 유지하고, “무작위 정책”은 행동마다 무작위로 고른다.
- `outcome_v1`은 봇 의사결정과 학습 환경 내부에서만 사용한다. **인게임에서 승률 예측을 보여 주지 않는다.** 사용자가 제공할 보드 Actor-Critic JSON과 전투 Actor-Critic JSON은 각각의 모델 어댑터로 연결한다.
- `prompt.md`는 커밋하지 않는다. 커밋은 브랜치에서 영어 Conventional Commits로 나누고 `main`에 `--no-ff`로 병합한다.

## 재현과 실행

```powershell
pnpm install
pnpm dev
```

웹 `http://localhost:5173/`, 서버 건강 검사 `http://localhost:3001/health`.

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm build
python -m pytest python/tests
pnpm exec prettier --check .
```

실측 기준은 `docs/game-design.md` §15와 `README.md`에 기록했다. 현재 내장 `rush-3` 모델의 4인 8,000판은 중앙 6라운드, 3라운드 내 탈락 22.6%, 용 처치 종료 46.8%다. 3인·2인은 각각 중앙 6·5라운드이고 용 처치 종료 33.6%·17.9%다. **목표보다 판이 짧고 조기 탈락 및 직업 격차가 크다.** 이 수치는 봇 정책을 포함한 시뮬레이션이며 실제 사람 경기 결과를 예측하지 않는다.

## 다음 작업

1. 사용자 제공 보드 및 전투 Actor-Critic JSON을 받으면 각 모델 레이아웃·버전·마스크에 맞는지 검증하고 연결한다. 두 모델은 별개의 학습 환경과 계약을 사용한다.
2. 에셋 목록은 `docs/development-plan.md` §4.2와 `docs/art-direction.md`를 따른다. 제공된 BGM 외의 SFX/이미지는 실제 파일이 생길 때 대체한다.
3. 밸런스 개선을 한다면 `rush-3` 결과를 기준으로 원인별로 측정한다. 2,000판 진단에서 3라운드 이전 탈락은 용 실패와 PvP가 거의 반반이었고, 3라운드 PvP 집중과 검사·광전사의 이른 용 도전이 주요 원인이었다. PvP 보호를 3라운드까지 늘리고 봇 용 도전을 4라운드 이후로 미루는 조합은 500판 예비 실험에서 조기 탈락을 줄였지만, 이는 아직 확정 규칙이 아니다. 사용자가 지정한 시작 방어막 제거와 PvP 보상은 임의로 되돌리지 않는다. 규칙/모델을 바꾸면 버전을 올리고 분포·모델을 다시 수집하고 2~4인별로 검증한다.
4. 배포 목적지와 실제 인터넷 회선에서의 체감 지연은 아직 확인이 필요하다. 가상 TCP 지연/손실 및 실제 Socket.IO 통합 테스트는 저장소에 있다.

## 구조 메모

- 보드 엔진은 결정적이며 게임 규칙의 단일 출처다. 온라인은 서버가 좌석·합법 행동·상태 버전을 검증한다. `packages/engine`의 수치 변경은 `RulesConfig`와 문서·골든 테스트를 함께 갱신한다.
- 전투는 `packages/combat`, 전투 AI는 `packages/combat-ai`, 롤백 네트코드는 `packages/netcode`다. `packages/ai`는 보드 AI다.
- 기존 `obs_v1`/`act_v1`과 전투 `cobs_v1`/`cact_v1`을 조용히 변경하지 않는다. 가중치 호환성이 걸려 있다.
- 로컬 화면과 온라인 화면은 같은 웹 UI를 공유한다. 보드 UI의 행동은 서버/엔진에서 제공한 합법 행동을 통해 제출한다.
